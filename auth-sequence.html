Sequence Auth: Đăng nhập và đăng ký

Tài liệu này mô tả luồng xác thực hiện tại của dự án quanlytro-api. API dùng Laravel Sanctum, trả Bearer token, chuẩn hóa JSON bằng middleware force.json, và áp dụng rate limit 10 request/phút/IP cho đăng nhập, đăng ký.

Base route /api/v1 qua routes/api.php và routes/api/v1.php.
Public Auth POST /auth/login và POST /auth/register, có throttle:auth.
Token Sanctum token tên api_token, hết hạn sau 30 ngày.
Protected Auth POST /auth/logout và GET /auth/me yêu cầu auth:sanctum.

Sequence đăng nhập

Client Route/Middleware LoginRequest AuthController AuthService Database/Sanctum
1. Gửi POST /api/v1/auth/login
Email + password
2. force.json đặt header Accept JSON; throttle:auth giới hạn 10 lần/phút/IP
3. Chuẩn hóa email: trim + strtolower
4. Validate: email bắt buộc, đúng định dạng; password bắt buộc
Sai dữ liệu: trả 422 + errors
5. Gọi AuthService::login() với dữ liệu đã validate
6. Auth::attempt($credentials)
7. Kiểm tra user và password hash trong bảng users
Email/password sai: throw BusinessException mã 401
8. Nếu is_active = false: logout session và trả 403
9. Xóa token cũ cùng tên api_token
10. Delete trong personal_access_tokens theo user + token name
11. Tạo token mới: createToken('api_token', expiresAt: now()+30 days)
12. Lưu hash token và expires_at vào personal_access_tokens
14. Nhận JSON gồm user, access_token, token_type, expires_at
13. Trả 200 OK qua UserResource

Sequence đăng ký

Client Route/Middleware RegisterRequest AuthController AuthService Database/Sanctum
1. Gửi POST /api/v1/auth/register
Name, email, password, password_confirmation, phone
2. force.json + throttle:auth
3. Chuẩn hóa email; phone chỉ giữ chữ số bằng preg_replace('/\\D/', '')
4. Validate name, email unique, password min 8 + confirmed, phone 10-11 chữ số
5. Kiểm tra unique email trong bảng users
Sai dữ liệu hoặc trùng email: trả 422 + errors
6. Gọi AuthService::register() với dữ liệu đã validate
7. Hash password bằng Hash::make(), đặt is_active = true
8. Tạo user mới bằng User::create($data)
9. Insert vào bảng users
10. Gán role landlord bằng Spatie Permission
11. Ghi quan hệ role cho user
12. Tạo Sanctum token api_token, hết hạn sau 30 ngày
13. Insert token hash vào personal_access_tokens
15. Nhận JSON gồm user, access_token, token_type, expires_at
14. Trả 201 Created qua UserResource

Endpoint và lỗi chính

Endpoint Middleware Điều kiện Kết quả
POST /api/v1/auth/login public force.json, throttle:auth Email/password hợp lệ, user tồn tại, password đúng, is_active = true. 200 OK, trả Bearer token. Token cũ tên api_token của user bị xóa trước khi cấp token mới.
POST /api/v1/auth/register public force.json, throttle:auth Email chưa tồn tại, password xác nhận khớp, phone nếu có phải 10-11 chữ số. 201 Created, tạo user active, gán role landlord, trả Bearer token.
POST /api/v1/auth/logout auth auth:sanctum Header Authorization: Bearer <token> hợp lệ. Xóa token hiện tại trong personal_access_tokens, trả thông báo đăng xuất thành công.
GET /api/v1/auth/me auth auth:sanctum Bearer token hợp lệ, chưa hết hạn. Trả thông tin user qua UserResource.

Nhánh lỗi cần chú ý

  • 422 Unprocessable Entity: request không hợp lệ, ví dụ thiếu email/password, email sai định dạng, email đăng ký đã tồn tại, password không khớp confirmation.
  • 401 Unauthorized: đăng nhập sai email hoặc mật khẩu; hoặc truy cập route protected khi chưa có token/hết phiên.
  • 403 Forbidden: user đăng nhập đúng nhưng is_active = false.
  • 429 Too Many Requests: vượt 10 request/phút/IP trên login/register.

Cách gọi các route protected sau khi đăng nhập/đăng ký

Authorization: Bearer <access_token>
Accept: application/json

Token trả về chỉ hiển thị một lần ở response. Trong database, Sanctum lưu hash của token trong bảng personal_access_tokens, không lưu plain text token.
